# Phase 7 — Printable report, QR code and verify page

**Goal:** either party can print or save a clean PDF of any locked report or the comparison, with a QR code that opens a public page proving the report has not been changed. Target time: 45 min.

**Read first:** `docs/SPEC.md` §3 F20–F21, §4 N05, §6.

## Tasks

- [ ] **7.1 Print route** `/t/[id]/print/[reportId]` (members only): A4-friendly layout with `@media print` CSS (hide nav/buttons, `break-inside: avoid` per item, 2–3 photos per row at small size). Header: "MoveProof condition report", type, address, parties (names + roles), lock time, self-attested badge, full report hash, QR code (generated server-side with `qrcode` → data URL) pointing to `${NEXT_PUBLIC_APP_URL}/verify/<reportId>`. Body: rooms → items with rating, notes, photos (signed URLs), each photo captioned with its server upload time and first 10 chars of its sha256. Footer: "Evidence record generated by MoveProof. Not a legal contract." A "Print / Save as PDF" button calls `window.print()`.
- [ ] **7.2 Comparison print** `/t/[id]/print/compare`: same style, side-by-side pairs for flagged items (all items optional toggle), deductions table, settlement summary, QR codes for both reports.
- [ ] **7.3 Verify page** `/verify/[reportId]` (public, no login): with the admin client, load the report tree, recompute the hash, and show:
  - Big result: "✓ Unchanged since <locked time>" if recomputed === `content_hash` and every signature's `report_hash` matches; "✗ Does not match" otherwise; "Not locked yet" for unlocked reports.
  - Report type, lock time, item and photo counts, signer roles + first names only, self-attested badge, stored hash and recomputed hash.
  - NO address, NO photos, NO emails, NO notes.
  - Optional input: "Paste the hash printed on your copy" → compares and shows match.
- [ ] **7.4 Links**: "Print" and "Verify" buttons on every locked report and on the comparison page; verify link also in the WhatsApp share text once a report is locked ("Our move-in report is locked. Verify it here: …").
- [ ] **7.5 Verification test** `scripts/verify-check.mjs`: for a given report id, recomputes the hash with the same `hash.ts` logic (import or duplicate minimal code) and prints match/mismatch — useful in the viva.

## Acceptance checks
- Chrome "Save as PDF" on a phone and laptop produces a readable PDF with photos and a scannable QR code.
- Scanning the QR opens `/verify/...` showing "Unchanged".
- Verify page for a non-existent id shows a friendly not-found state (no stack trace).
- lint, typecheck, test, build pass.
